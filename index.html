オフラインAPIキー生成

Web Crypto APIでクライアントサイド生成するため、サーバーに鍵を送信しません。 キーはHMAC-SHA256で署名する例を添付しています。

生成ボタンは在庫無制限です。無限にAPIキーを発行でき、すべてローカルで完結します。

  • SPD-プレフィックス + ランダムHEX（例: SPD-ABCD-1234-...）。
  • 各キーはHMAC署名やmTLSと組み合わせてDDoS/DOS/XSS対応ゲートウェイで検証。
  • WebhookやREST呼び出し時に X-API-KEY / X-SIGNATURE を必須化。

世界最強クラス仕様

  • FIPS 140-3準拠の暗号プリミティブを想定、Web CryptoはOSエントロピーを直接使用。
  • ポスト量子対応: Kyberベースの相互認証を組み合わせるアドオン設計。
  • 自動ローテーションAPIでキー寿命を最長24時間に制限、漏洩面を極小化。

署名付きリクエスト例

curl -X POST https://api.shieldpulse.io/v1/shield/analyze \
  -H "X-API-KEY: SPD-XXXXX" \
  -H "X-SIGNATURE: hmac-sha256(...)" \
  -d '{"payload":""}'

生成履歴 (最新5件)

    履歴はブラウザを更新すると消去されます。使い終わったキーは即座に無効化してください。

    API ドキュメント

    全エンドポイントはIdempotentキー検証、WAF前段、mTLS(+ fallback)を標準搭載。

    Method Endpoint Purpose
    POST /v1/shield/analyze リクエスト指紋を評価し、適用すべきポリシーを返す。
    POST /v1/shield/verify Webhook署名やmTLS証明書ピンニング結果を検証。
    GET /v1/telemetry/health レートリミット消費量やブロック統計をリアルタイム取得。

    APIキー検証フロー

    1. クライアントはSPDキーでリクエストに署名し、DOS/DDoS緩和用のゲートウェイへ送信。
    2. ゲートウェイはレート制限 → シグネチャ検証 → ルールベースWAFの順で検査。
    3. 異常検知時はキーを即時ローテーションし、新しいキーをこのページで無限に再発行。

    XSS対策として、UIはCSPでインラインスクリプトを禁止し、全フォームをSameSite=Laxにする設計です。

    レート制限 参考値

    推奨: 120 req/min, 5 req/sec ハードリミット。

    計算結果は単純化されたモデルです。実運用ではL4/L7の観測結果と合わせて調整してください。

    よくある質問

    このテンプレートはGitHub Pagesでそのまま動きますか？

    はい。すべてのアセットはリポジトリ内相対パス参照です。リポジトリ設定でPagesを有効化すれば公開できます。

    実際のDDoS軽減機能は含まれますか？

    本テンプレートはベストプラクティスとUIを提供します。実際の軽減はあなたのインフラへ連携してください。

    APIキーをどこに保存すれば安全ですか？

    AWS Secrets ManagerやHashiCorp VaultなどのKMS/Secretストアに保存し、環境変数で読み出してください。
